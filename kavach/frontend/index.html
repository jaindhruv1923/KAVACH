    R(x) = σ(w_1 · S_action(x) + w_2 · max(Sev(f)) + w_3 · H_Shannon(x))

    Maps operation action risk, detected entity severity tiers, and Shannon entropy into bounded risk score R(x) ∈ [0, 1].

    I(f_i, q) = α · Cosine(e_q, e_f_i) + (1 - α) · AST_Graph_Centrality(f_i)

    Combines dense sentence vector embeddings (Qdrant) with static AST call-graph in-degree centrality (α = 0.6).

    H_Shannon(s) = -∑ p_i · log_2(p_i)

    Empirically gates high-entropy API keys (>3.0 bits/char) while avoiding false alarms on readable placeholders.

    Abstract

    Autonomous Agentic AI developers (e.g., SWE-agent, Devin) promise automated bug-fixing, feature implementation, and CI/CD operations. However, deploying unconstrained autonomous agents in enterprise software ecosystems introduces catastrophic vulnerabilities: (i) package hallucinations and "slopsquatting" attacks, where agents invoke non-existent modules subsequently weaponized by adversaries on public registries; (ii) data exfiltration of sensitive identifiers (PII/SPDI) and API credentials into third-party cloud LLM contexts, violating localization regulations such as the Indian Digital Personal Data Protection (DPDP) Act 2023; (iii) unbounded blast radiuses causing cascading breaking changes; and (iv) non-convergent debugging loops.

    To address these vulnerabilities, this paper introduces KAVACH, an enterprise-grade, deterministic, security-governed agentic DevOps framework. KAVACH implements a three-tier lifecycle inspection topology ($Input \rightarrow RAG \rightarrow Patch$) featuring: (1) an Abstract Syntax Tree (AST) Package Hallucination Firewall that statically intercepts imports and audits them against registry caches to prevent supply-chain hijacking; (2) a Zero-Knowledge Token Vault providing reversible identifier de-identification before external API dispatch; (3) an AST-guided semantic change-impact analyzer; and (4) cryptographic CycloneDX Software Bill of Materials (SBOM) generation satisfying SLSA Level 3 provenance. Empirical evaluation across 100 software packages and 100 multilingual developer prompts demonstrates that KAVACH achieves a 100.0% catch rate against package hallucinations, 0.990 F1 on code-mixed Hinglish PII detection, and improves patch validity to 93.4% via sandboxed AST reflexion—all with an overhead of under 47 ms (<2.5% total lifecycle latency).

    Section I: Introduction & Motivation

    The rapid evolution of Large Language Models (LLMs) from passive autocomplete assistants to autonomous, tool-calling software engineering agents represents a fundamental paradigm shift. Modern agentic frameworks are capable of decomposing complex natural language requirements, querying vector databases via Retrieval-Augmented Generation (RAG), editing multi-file software repositories, and generating automated continuous integration (CI) tests.

    Despite their software development capabilities, deploying unconstrained agentic architectures in regulated industrial settings introduces critical security, governance, and supply-chain vulnerabilities: package hallucination, code-mixed PII spillage, and unbounded code drift. KAVACH treats security as a first-class citizen governed directly within the agent's finite state machine.

    Section II: Threat Model & Problem Formulation

    We consider an active adversary $\mathcal{A}$ attempting to exploit autonomous coding agents through package slopsquatting, eavesdropping on LLM cloud API transcripts, or injecting adversarial prompt delimiters. KAVACH formulates continuous risk scoring functions using weighted action risks, entity severity, and Shannon entropy.

    Section III: System Architecture & Subsystems

    Detailed technical description of Pre-Flight Intent Shield, Multilingual Zero-Knowledge Token Vault, In-Flight AST-RAG Blast-Radius Analysis, Post-Flight AST Package Firewall, and CycloneDX v1.5 Cryptographic Attestation Ledger.

    Section IV: Algorithm 1 (AST Package Firewall)

    Formal AST traversal extracting ast.Import and ast.ImportFrom nodes, normalizing module names, checking local project boundaries and standard library modules, querying the verified registry cache, and flagging missing packages before execution.

    Section V: Experimental Evaluation & Baselines

    Quantitative evaluation answering RQ1 (Supply Chain Defense), RQ2 (Multilingual PII Governance), RQ3 (Component Ablation), and RQ4 (Runtime Latency Overhead).

    Section VI: Scientific Limitations & Future Scope

    Honest disclosure of current boundaries: bare numeric sequence disambiguation without contextual keywords, and moving from static registry checks to dynamic binary sandbox evaluation in future iterations.
