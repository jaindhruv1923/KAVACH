## 5. The 5 Mathematical Formulations (Explained with Simple Analogies)
*Dr. Soharab and Mr. Pranshu love asking about the math. Here is each formula explained in plain English:*

### 1. Dihedral Group ($D_5$) Verhoeff Checksum (Aadhaar Verification)
* **Simple Explanation:** Most websites use a basic "Luhn" check or regex that only checks if there are 12 digits. But Luhn misses when two neighbor numbers get accidentally swapped (like typing `12` instead of `21`).
* **The Math:** The Indian Aadhaar algorithm uses the **Dihedral Group of order 10 ($D_5$)**, which represents the geometric rotations and reflections of a 5-sided pentagon.
* **Why it works:** It uses two lookup tables (a multiplication table and a permutation table). It is mathematically proven to catch **100% of single-digit typos** and **100% of adjacent number swaps**. If the final result $c \ne 0$, the number is fake.

### 2. Shannon Information Entropy ($H \ge 4.5$) (Secret Key Detection)
* **Simple Explanation:** How do you catch a leaked secret key (like an AWS password or GitHub token) if you don't know what it starts with? You measure how **random** it looks.
* **The Math:**
  $$H(X) = -\sum P(x_i) \log_2 P(x_i)$$
* **Why it works:** Normal English words (like `"database_connection"`) have predictable repeating letters, so their entropy is low ($H < 3.5$). But cryptographic secret keys look like total gibberish (e.g., `AKIAIOSFODNN7EXAMPLE`), giving them a very high entropy ($H \ge 4.5$). Any long random string is immediately quarantined.

### 3. AST Blast-Radius Reachability Metric $B(v) > 0.35$
* **Simple Explanation:** Before an AI modifies a function, how do we know it won't break the entire application?
* **The Math:** We build a directed graph $G = (V, E)$ of every function and class. For any modified function $v$:
  $$B(v) = \frac{|\text{Reachable}(v)|}{|V| - 1}$$
* **Why it works:** If $B(v) = 0.40$, it means modifying that one function ripples through and touches 40% of the entire codebase. Our rule states: **if $B(v) > 0.35$, halt immediately and demand Human-In-The-Loop approval!**

### 4. Dense Cosine Similarity Gating ($\ge 0.70$) in Qdrant RAG
* **Simple Explanation:** When searching past code to help the AI, we must make sure the retrieved files are actually relevant.
* **The Math:** We turn code chunks into 384-dimensional vectors using `all-MiniLM-L6-v2` and measure the cosine angle between vectors:
  $$\cos(u, v) = \frac{u \cdot v}{\|u\|_2 \|v\|_2}$$
* **Why it works:** Any retrieved chunk scoring below $0.70$ is thrown away. This prevents the LLM from getting confused by irrelevant code snippets.

### 5. NIST FIPS 202 SHA3-512 Cryptographic Merkle DAG
* **Simple Explanation:** If an attacker modifies an old log entry in the database, how do you catch them?
* **The Math:** Every single action is hashed using the Keccak SHA3-512 cryptographic hash function. Each new hash includes the hash of the previous event:
  $$\text{Root}_k = \text{SHA3-512}(\text{Root}_{k-1} \,\|\, \text{TaskID} \,\|\, \text{Stage} \,\|\, \text{Payload})$$
* **Why it works:** Like a blockchain, if anyone tampers with a historical transaction, every subsequent hash in the chain breaks, immediately exposing the tampering.
